# rblat development notes

Goal: run the BLAT engine entirely inside R via a compiled C backend (`.Call`),
with **no `system()` calls** to an external `blat` binary. Intended as an
in-process replacement for the command-line blat step in `trellis`.

## Status: Phases 0–7 complete

**Phase 0 — ground truth (done).**
- Base fork: **djhshih/blat** (not pblat). Cleaner build, self-contained test
  data, no htslib. pblat's threading is harmful inside a single `.Call`
  (R callbacks + genoFind globals are not thread-safe); parallelize at the R
  level instead if ever needed.
- Building the full upstream `jkweb.a` fails (pngwrite→libpng, and would also
  hit https/mysql/bamFile). We must compile only the subset blat links.
- Minimal object set derived empirically: compile every `lib/*.c` +
  `jkOwnLib/*.c` that compiles cleanly (only `oswin9x`, `pngwrite`, `vGif`
  fail — none needed), archive them, link `blat.o`, and read the linker's
  `-Wl,-why_load` output. Result: **67 objects**, all compile on macOS
  clang/arm64, link with just `-lz -lm`, zero undefined symbols. Those 67 `.c`
  are what `src/` contains.

**Oracle strategy (important):** the committed reference PSLs in the upstream
`test/` dir were generated by a *different* blat version — `v29skips/ex1` does
NOT reproduce with this repo's own v35 binary (it emits 1 block, the reference
expects a spliced 2-block alignment), and `intron50k/expected/` is not even in
the repo. So goldens are **generated from our own build of the vendored source**
(see `inst/extdata/*/golden.psl`), and the correctness bar is "rblat matches the
blat binary built from the identical vendored source." `v29skips/ex2` does
reproduce byte-exactly and is a good regression case.

**Phase 1 — compiling package skeleton (done).**
- `src/Makevars`: relies on R's default rule (compiles all `src/*.c`). Key flag:
  **`-std=gnu17`** — R 4.6 uses `-std=gnu23`, under which the Kent code's K&R
  empty-paren prototypes (`void f()`, function-pointer params) are reinterpreted
  as `(void)` and rejected (`common.c:360`). Our `-std` appears later on the
  command line and wins.
- `src/rblat_init.c`: registers one `.Call` (`C_rblat_version`) that calls the
  real engine symbol `dnaUtilOpen()` and returns a banner — proves the engine is
  linked AND runtime-callable. Kent headers are NOT included here (their
  `common.h` redefines TRUE/FALSE/boolean, clashing with R headers); the one
  symbol used is forward-declared.
- `R CMD INSTALL` succeeds with **zero warnings**; `rblat::rblat_version()`
  returns the banner.

**Phase 2 — file-in / file-out MVP (done).**
- `rblat(database, query, ...)` runs BLAT **in-process via `.Call`** (no
  `system()`), returns the 21-column PSL data.frame (`blat_colnames`, matches
  trellis). Database/query are FASTA paths for now; output goes to a tempfile
  that `readPsl()` parses.
- Three C files added on top of the 67 vendored objects:
  - `rblat_blat.c` = surgical copy of `blat.c`: `main`→`rblat_blat_main`;
    `#define exit(code) errAbort(...)` after includes so every `exit()` is
    catchable; `rblat_reset_globals()` at entry (resets the option globals AND
    calls `optionFree()`); `showStatus` gated on a `rblat_quiet` global.
  - `rblat_engine.c` = `errCatch` guard exposing plain-C `rblat_run_argv()`
    (Kent headers only).
  - `rblat_init.c` = R-facing `.Call` (`C_rblat_run`); builds a **writable**
    argv (optionInit mutates argv strings/array in place — passing `CHAR()`
    pointers would corrupt R's string pool) and turns caught errors into
    `Rf_error`.
- Also had to vendor **`errCatch.c`** — it wasn't in the 67-object set because
  `blat.o` itself never uses errCatch (only our wrapper does).
- **Two bugs found and fixed during Phase 2:**
  1. C23/K&R already handled in Phase 1 via `-std=gnu17`.
  2. `options.c` caches the parsed command line in a `static struct hash
     *options` populated only when NULL, so the **2nd call in a session skipped
     argv stripping** → wrong argc → `usage()`/exit. Fixed by calling
     `optionFree()` in `rblat_reset_globals()`.
- Tests: `tests/testthat/test-rblat.R` (testthat not installed here; equivalent
  standalone checks all pass: small==golden, ex2==golden on 2nd call,
  repeatability on 3rd call, no-hit empty frame, malformed input → clean
  `Rf_error` with the R session surviving). **10/10 pass.**

**Phase 3 — in-memory output (done).**
- `rblat()` now returns the 21-column PSL data.frame **directly from C** — no PSL
  text, no output file. Input is still FASTA paths (Phase 4). Verified: goldens
  match byte-for-byte, no-hit → empty well-typed frame, 40-hit synthetic query
  exercises the array-growth path, repeatable across calls.
- Three-part split preserves the R/Kent header firewall:
  - `rblat_collect.c` (Kent headers) — `struct rblatResult` growable arrays plus
    `collectPslx()`, a faithful copy of `savePslx()`'s match/mismatch/repMatch/N/
    insert counting and identity filter; only the final "emit a record" step
    differs — where savePslx does `fprintf`, we append to arrays. Comma-terminated
    block strings are built with the same `"%ld,"`/`"%d,"` formats so they equal
    the .psl fields. `rblatOutputCollector()` builds a `gfOutput` with our `out`
    callback and no `fileHead`/`queryOut` hooks.
  - `rblat.h` (R- and Kent-safe: plain C types only) — defines `struct
    rblatResult` (21 columns as `int*`/`char**`), so the R side reads it without
    Kent headers. Adds `rblat_result_new/free`, `rblat_blat_set_collector`,
    `rblat_run_argv_collect`.
  - `rblat_init.c` (R headers) — `C_rblat_run_collect` builds a writable argv,
    runs the collector, and assembles the data.frame (`INTSXP`/`STRSXP` columns,
    names, `class="data.frame"`, compact `row.names = c(NA,-n)` to match
    `readPsl()`), then frees the result.
- `blat()`/`rblat_blat_main()` gained a collect mode: a `static struct
  rblatResult *rblat_collect_result` (set via `rblat_blat_set_collector()`).
  When armed, `blat()` opens **no** output file (`FILE* = NULL`, which every
  downstream `carefulClose()` tolerates) and uses `rblatOutputCollector()`
  instead of `gfOutputAny()`; `rblat_blat_main()` then expects argc==3 (no
  output-path arg). The engine disarms the collector after each run, including
  on the errAbort/exit longjmp path.
- The Phase-2 file path (`C_rblat_run` + `readPsl` + `blat()`'s `FILE*` branch)
  is retained and still works; `readPsl()`/`blat_colnames` remain exported and
  are used to read the goldens.

**Phase 4 — in-memory input (done).**
- `rblat(database, query, ...)` now accepts **in-memory sequences** — a *named*
  character vector (names = sequence ids) or a Biostrings `DNAStringSet` — for
  either/both arguments, in addition to FASTA file path(s). When both are
  in-memory the whole run touches **no files** (no input FASTA, no output PSL,
  no `system()`).
- `R/rblat.R` gained `.rblat_seq_input()`, which classifies each argument:
  `XStringSet` → sequences; *named* character → sequences; *unnamed* character
  that are all existing paths → file mode; anything else → a clear error. db and
  query must use the same style (mixed → error). In-memory calls dispatch to
  `C_rblat_run_collect_mem` with two placeholder positional argv args so blat's
  `argc==3` check still passes; file calls keep using `C_rblat_run_collect`.
- C side:
  - `rblat_input.c` (new, Kent headers) — `rblat_seqs_from_arrays(names, seqs,
    n)` builds a `dnaSeq` list (cloned, order-preserving). Sequences are copied
    verbatim, exactly what `faMixedSpeedReadNext()` returns from a `.fa`; case
    conversion happens downstream, so results are byte-identical to file input.
  - `rblat_blat.c` — a collect-style arm: `static boolean rblat_mem_input` +
    `rblat_db_seqs`/`rblat_query_seqs`, set via `rblat_blat_set_inputs()`. In
    memory mode `blat()` skips `gfClientFileArray`/`gfClientSeqList`, uses the
    db list directly (applying `faToDna`/`faToProtein` like gfClientSeqList's
    no-mask path), and does **not** free it (caller owns it — avoids a double
    free). `searchOneIndex()` iterates `rblat_query_seqs` instead of opening
    query files. `-mask`/`-repeats`/`-makeOoc` and translated (dnax/rnax) modes
    are rejected with a clean `errAbort` in memory mode (they need files / the
    bigBlat query path, which re-reads per strand — Phase 5).
  - `rblat_engine.c` — `rblat_run_argv_collect_mem()` builds the two dnaSeq
    lists, arms collector+inputs, runs main under errCatch, disarms on the
    longjmp path too, and frees both lists (single owner).
  - `rblat_init.c` — `C_rblat_run_collect_mem` (5 args) borrows R's string pool
    as `char**` (engine cloneStrings what it keeps) and reuses
    `rblat_result_to_df`.
- Verified: in-memory == file == golden for `small` and `v29skips/ex2`; empty
  no-hit frame; repeatable and interleavable across calls; `DNAStringSet` path;
  dispatch errors (mixed / unnamed-non-file / translated) are clean with the R
  session surviving; a 300× stress loop + a 50-query multi-hit run + `gc()` show
  no crashes or double-frees. **Test suite 23/23.**

**Phase 5 — options & modes (done).**
- `rblat()` exposes the full common option set: `minScore`, `minMatch`,
  `tileSize`, `stepSize`, `minIdentity`, `maxGap`, `maxIntron`, `repMatch`,
  `t`/`q` (dna/prot/dnax/rnax/rna), `mask`, `qMask`, `ooc`, `oneOff`, `fastMap`,
  plus a raw `args` escape hatch.
- **Key design change:** the numeric options now default to `NULL` = "use BLAT's
  own default", and a flag is emitted only when the user sets it. BLAT's defaults
  are *type-aware* (tileSize 11 vs 5, minMatch 2 vs 1, minIdentity 90 vs 25 for
  DNA vs protein/translated), so hard-coding DNA numbers — as the wrapper did
  through Phase 4 — silently broke protein/translated searches (blat rejects
  tileSize 11 for protein). Small helpers (`int_opt`/`num_opt`/`str_opt`) build
  the flag vector. DNA behavior is unchanged: the ex2 default run still matches
  the golden byte-for-byte (verified), because blat applies the same numbers.
- Mode coverage verified end to end: **dna/dna** and **prot/prot** (the latter
  via blat's auto tileSize=5) both run; a spliced query produces a correct
  2-block **intron** alignment (blockSizes/qStarts/tStarts each carry
  `blockcount` comma-terminated entries, blocks sum to `match`, target gap ==
  intron); **minIdentity** filters (95%-id hit kept at 90, dropped at 98);
  **dnax/dnax** works in file mode and exercises the collector's two-char
  `++`/`--` strand (reportTargetStrand) path.
- Compatibility guards: `mask` (target masking) and non-existent `ooc` files are
  rejected with a clear R-level error before the `.Call`; `qMask` (case-based)
  is allowed with in-memory input; translated modes with in-memory input still
  errAbort in the C layer (see below). **Test suite 45/45.**

**Phase 6 — robustness (done).**
- *exit/longjmp safety (audited + confirmed).* The only `exit()` call sites in
  the whole vendored tree are `errabort.c`'s `defaultAbort` (replaced by
  errCatch's longjmp handler whenever an errCatch is on the stack — always true
  during a run) and `pipeline.c`'s forked-child paths (never reached: blat with
  FASTA/in-memory input spawns no subprocess pipeline). `blat.c`'s own `exit()`s
  (usage, makeOoc) are neutralized by the `#define exit(code) errAbort(...)` in
  `rblat_blat.c`. Net: every abort during a run longjmps back through errCatch;
  nothing terminates the R process. A regression test hammers the errAbort path
  25× and confirms a subsequent normal run is byte-identical.
- *reentrancy (audited + confirmed safe for sequential calls).* File-scope
  statics in the alignment TUs are all benign: const tuning (`gfNearEnough`,
  `usualExpansion`, `modSize`, `tileStrinProbMult`), an idempotent lazy-init
  lookup table (`ntLookup`/`initted` — same values every time), a per-op memory
  pool that is `lmInit`/`lmCleanup`-balanced (`ffMemPool`), or set-before-use
  scratch (`cmpQuerySize`, `ss*`, `rw*`). Options that persist via setters
  (`setFfIntronMax`, `setFfExtendThroughN`, `extendThroughN`) are re-applied
  every run by `rblat_blat_main`, and `rblat_reset_globals()` resets all of
  blat.c's option globals + `optionFree()`. The Phase 0 thread-safety warning
  was about *parallel* use; rblat is strictly sequential per `.Call`.
- *memory leaks (fixed the two per-call ones).* Upstream `blat.c` never frees
  the genoFind index (`gf`) or the output controller (`gvo`) — harmless in a
  one-shot binary, but rblat runs many times per R session. Added
  `genoFindFree(&gf)` (simple branch) and `gfOutputFree(&gvo)` (both branches);
  for the collector, freeing `gvo` releases only the small data wrapper, not the
  result rows (caller-owned). Verified by RSS: **8000 real calls** (2000×
  interleaving in-memory + file + two error paths) grew RSS by ~0 MB (flat).
- *warn() routing (new).* errCatch already *captures* blat `warn()` text into
  its message buffer; the engine now returns that (on success) via a new
  `warnMsgOut`, and `rblat_init.c`'s `rblat_emit_warning()` re-raises it as an R
  `warning()` (trailing newline trimmed). E.g. a >5 Mb query now yields an R
  warning instead of silent stderr output; normal runs emit none.
- *tooling note.* valgrind is unavailable on Apple Silicon and LeakSanitizer is
  unsupported on Darwin; an AddressSanitizer harness linking the pure-C engine
  (everything but `rblat_init.c`) built cleanly but ASan's runtime hangs at
  process start on this toolchain (before `main`), so leak/UB checking relied on
  the RSS-growth loop + the 101-test suite (error recovery, repeatability,
  warnings) instead. **Test suite 101/101.**

**Phase 7 — trellis integration (done).**
- Goal: prove `rblat()` is a drop-in for the external command-line blat step
  trellis relies on — **without depending on or editing the `trellis` package.**
  Per the request, no trellis source was touched; all verification lives inside
  rblat.
- How trellis uses blat: it does *not* shell out itself. External command-line
  blat writes `.psl` files, which trellis reads via `readBlat()` (==
  `read.delim(skip = 5, header = FALSE)` + `blat_colnames`) and feeds to
  `annotateBlatRecords`/`blatScores`/`blatGRanges`. So the integration contract
  is purely "produce the identical `blat_colnames` data.frame."
- Fixtures: `svbams/data-raw/blat_test.R` is the canonical small blat exercise —
  it runs `blat -minScore=0 -stepSize=1 <ref> <query>` on two fixture pairs.
  Vendored those inputs **and their real command-line-blat goldens** into
  `inst/extdata/trellis/` (`ref{1,2}.fa`, `query{1,2}.fa`, `golden{1,2}.psl`;
  provenance in that dir's `README.md`). Keeps rblat's tests hermetic — no
  runtime dependency on a trellis/svbams install.
- Result: `rblat(ref, query, minScore = 0, stepSize = 1)` reproduces both
  command-line-blat goldens **byte-for-byte** (`expect_equal` to `readPsl`),
  file-based and in-memory, and matches a locally-emulated `readBlat()`
  (`read.delim(skip = 5)` + `blat_colnames`) column-for-column. The two
  invariants the svbams script documents (fixture 1 → two single-block hits;
  fixture 2 → `blockSizes == "50,50,"`) are asserted too. **Test suite 112/112.**
- Adoption is trellis's own future choice: rblat is a ready provider (call
  `rblat()` instead of `system(blat ...)` + `readBlat()`), but rblat does not
  force that change.
- Documented in `vignettes/rblat.Rmd` ("In-process BLAT: replacing the
  command-line blat step"): motivated by the trellis re-alignment step, it shows
  (1) the one-line drop-in for `system(blat …)` + `readBlat()`, (2) the
  file-free in-memory path (named vector / `DNAStringSet`), and (3) a sketch of a
  future direct trellis integration (`tags` data.frame → `rblat()` →
  `annotateBlatRecords`). Its equivalence chunks execute against the bundled
  goldens at build time (all `identical(...) == TRUE`); the trellis-side chunks
  are `eval=FALSE` illustrations (no trellis dependency). Added
  `VignetteBuilder: knitr` + `knitr`/`rmarkdown` to DESCRIPTION Suggests.

### Known limitations / future follow-ups
- In-memory input supports only simple **dna/dna** and **prot/prot**; translated
  modes (`-t=dnax`, `-q=rnax`, protein-vs-dna) still require FASTA files because
  `bigBlat` re-reads the query per strand (would need per-strand cloning). They
  work fine from files.
- In-memory input rejects file-based target masking (`-mask=out/file.out`) and
  needs real files for `-ooc`; case-based `-qMask` works in memory, but
  case-based **target** `-mask` does not (the in-memory db is `faToDna`'d, which
  discards the soft-mask case). Lifting these is grouped with the translated
  in-memory work.
- `rblat_quiet` is hard-wired on (status printf's suppressed); not yet a param.
- The collector holds all rows in memory before building the data.frame; fine
  for typical trellis-scale queries, revisit only if a single run must stream
  millions of alignments.
- Per-call `gf`/`gvo` leaks are fixed (Phase 6), but the *rest* of the upstream
  tree has not been exhaustively leak-audited — impractical without valgrind on
  this platform. RSS is flat across thousands of calls, so any residual leak is
  negligible in practice.
